## 从两数之和出发

给定整数数组 `nums`，找出所有和为 `0` 的三元组。三个数必须来自不同的下标，答案中不能出现重复的数值组合。

我的想法是：既然已经可以用哈希集合解决两数之和，那么三数之和能不能拆成多次两数之和？

固定一个数 $a$，剩下两个数 $b$、$c$ 就需要满足：

$$
b+c=-a
$$

因此，外层遍历固定 `nums[i]`，内层在它后面的数组中寻找目标和为 `-nums[i]` 的数对。这样不用从头设计寻找三个数的过程，主要需要解决的是：**如何保证三个下标不同，以及如何避免重复答案。**

## 排序，并且只搜索当前位置之后的元素

先对整个数组排序。固定 `nums[i]` 后，只把后缀传给两数之和：

```java
int[] slice = Arrays.copyOfRange(nums, i + 1, nums.length);
res.addAll(twoSum(slice, -nums[i]));
```

`copyOfRange` 的范围左闭右开，因此 `slice` 不包含当前固定的元素，内层不会再次使用它所在的位置。

例如，排序后的数组为：

```text
[-4, -1, -1, 0, 1, 2]
```

固定下标 `1` 的 `-1`，就在 `[-1, 0, 1, 2]` 中寻找和为 `1` 的数对，得到 `[-1, 2]` 和 `[0, 1]`。

这里允许两个不同位置上的数值相同。固定第一个 `-1` 后，后缀中的另一个 `-1` 仍然可以参与组成 `[-1, -1, 2]`。

## 内层去重：匹配成功后，删除较小的数

设两数之和的目标为 `target`，当前遍历的数为 `v`，它的配对值为：

```java
int other = target - v;
```

由于后缀有序，可以分三种情况处理。

### 当前数小于配对值

当 `v < other` 时，配对值比当前数大，可能在后面出现。把 `v` 放入集合，留给后续元素匹配。

相同的较小值即使出现多次，`HashSet` 中也只保存一份。

### 当前数大于配对值

当 `v > other` 时，较小的配对值如果存在，应该已经被遍历过。查询集合，匹配成功后记录答案，并立即删除 `other`。

例如 `target = 4`，后缀为 `[1, 1, 3, 3]`：

| 当前数       | 操作               | 集合    | 新增数对   |
| ------------ | ------------------ | ------- | ---------- |
| 第一个 `1` | 加入集合           | `{1}` | 无         |
| 第二个 `1` | 重复加入，集合不变 | `{1}` | 无         |
| 第一个 `3` | 找到并删除 `1`   | `{}`  | `[1, 3]` |
| 第二个 `3` | 找不到 `1`       | `{}`  | 无         |

**这里真正保证去重的是排序与删除共同起作用。**记录 `[1, 3]` 后，数组后面不会再出现 `1`，所以被删除的 `1` 不会重新进入集合。

如果数组无序，比如 `[1, 3, 1, 3]`，后面的 `1` 会重新加入集合，第二个 `3` 就又能匹配一次。因此，这个辅助方法不能脱离“输入已经排序”的前提单独使用。

### 当前数等于配对值

当 `v == other` 时，需要两个数值相等、下标不同的元素。

例如 `target = 4`，只有一个 `2` 不够，至少要有两个 `2`。但 `[2, 2, 2, 2]` 也只能贡献一次数对 `[2, 2]`。

因此，单独统计满足 `v == other` 的元素个数，遍历结束后，如果个数至少为 `2`，就添加一次答案。

原先写法中的 `flag++ == 0` 实际上是在相等时计数；这里把计数单独写出来，相等的元素也不再放入集合。

## 外层去重：跳过重复的固定值

内层去重只能保证一次 `twoSum` 调用中没有重复数对。不同的外层调用仍可能产生相同三元组，因此还需要：

```java
if (i > 0 && nums[i] == nums[i - 1]) continue;
```

排序之后，相等的固定值相邻。第一次固定该值时，它后面的元素已经覆盖了后续相同固定值能够使用的所有元素，因此后续调用不会带来新的数值组合。

这并不意味着禁止答案中出现两个相同的数。例如 `[-1, -1, 2]` 会在固定第一个 `-1` 时被找到。

## 完整 Java 实现

下面保留“排序、复制后缀、集合匹配后删除、相等数对单独计数”的设计。辅助方法返回三元组时，沿用 `[v, other, -target]` 的顺序；题目不要求三元组内部有序。

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

class Solution {
    // 前提：nums 已经按非递减顺序排序。
    private List<List<Integer>> twoSum(int[] nums, int target) {
        List<List<Integer>> res = new ArrayList<>();
        Set<Integer> set = new HashSet<>();
        int equalCount = 0;

        for (int v : nums) {
            int other = target - v;

            if (v < other) {
                set.add(v);
            } else if (v > other) {
                // remove 返回 true，表示配对值存在且已被删除。
                if (set.remove(other)) {
                    res.add(Arrays.asList(v, other, -target));
                }
            } else {
                equalCount++;
            }
        }

        if (equalCount >= 2) {
            res.add(Arrays.asList(target / 2, target / 2, -target));
        }

        return res;
    }

    public List<List<Integer>> threeSum(int[] nums) {
        Arrays.sort(nums);
        List<List<Integer>> res = new ArrayList<>();

        for (int i = 0; i < nums.length - 2; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;

            int[] slice = Arrays.copyOfRange(nums, i + 1, nums.length);
            res.addAll(twoSum(slice, -nums[i]));
        }

        return res;
    }
}
```

`set.remove(other)` 把“查询是否存在”和“存在时删除”合在了一步：删除成功返回 `true`，不存在返回 `false`。

代码中的整数加减按本题数值范围处理；如果推广到任意 Java `int` 输入，需要另行考虑取负与减法的溢出。

## 为什么不会漏解或重复使用元素

对于任意一个合法三元组，将数值按 $a\le b\le c$ 排列。

当外层固定 $a$ 时，后缀中保留了组成该三元组所需的另外两个位置。即使 $a$ 出现多次，只处理它第一次作为固定值的情况也足够，因为这一次的后缀包含最多的剩余元素。

- 如果 $b<c$，内层先遇到 $b$，把它放入集合；随后遇到 $c$ 时找到 $b$，记录答案。删除 $b$ 后，后面的重复 $c$ 无法再次匹配它。
- 如果 $b=c$，后缀中至少有两个这样的元素，`equalCount >= 2` 会记录一次答案。

内层不同值的匹配来自先后遍历到的两个位置；相等值要求出现至少两次；外层固定位置又不在后缀中。因此三个下标互不相同。

## 复杂度

设原数组长度为 $n$。假设哈希集合的插入、查询和删除平均为 $O(1)$：

- 排序的时间为 $O(n\log n)$。
- 固定一个元素后，复制后缀和扫描后缀都需要与后缀长度成正比的时间。
- 所有后缀长度相加为 $(n-1)+(n-2)+\cdots+2=O(n^2)$。

因此，整体期望时间复杂度为 **$O(n^2)$**。

不计答案，单轮的后缀数组和集合最多各占 $O(n)$ 空间，因此峰值额外空间为 **$O(n)$**。设输出三元组数量为 $k$，计入答案则为 $O(n+k)$。

每轮复制切片不会改变时间复杂度的阶，但会累计产生 $O(n^2)$ 的数组元素复制。后续可以让辅助方法接收原数组和起始下标，省去这部分复制，同时保留当前去重逻辑。

## 边界与易错点

| 情况                 | 应有结果或处理                                                       |
| -------------------- | -------------------------------------------------------------------- |
| `[0, 0, 0, 0]`     | 只输出一次 `[0, 0, 0]`：外层跳过重复固定值，内层相等数对只添加一次 |
| `[-2, 1]`          | 没有三元组；不能把唯一的 `1` 使用两次                              |
| `[-2, 1, 1]`       | 可以组成 `[-2, 1, 1]`，因为两个 `1` 的位置不同                   |
| `[-2, 0, 0, 2, 2]` | 只输出一次数值组合 `[-2, 0, 2]`                                    |
| 后缀没有排序         | 不能直接使用删除配对值的去重逻辑                                     |
| 外层不跳过重复值     | 不同调用仍可能返回同一个三元组                                       |

这份解法的关键是：**用排序限制元素出现的先后顺序，用删除消耗已经输出过的不同值数对，再单独处理相等的两个数。**
