## 每次递归只决定下一段

给定字符串 `s`，把它分割成若干非空子串，要求每一段都是回文，返回全部分割方案。例如 `"aab"` 的答案是：

```text
[["a", "a", "b"], ["aa", "b"]]
```

这题让我困惑的地方不是如何判断回文，而是：递归每一层负责什么？进入下一层后，上一层在哪里等待？为什么返回后还要删除刚才加入的字符串？

可以先给递归一个明确的约定：**`dfs(s, i)` 进入时，`ans` 已经合法分割了前 `i` 个字符；当前调用负责枚举剩余后缀的分割方式，结束时恢复进入时的 `ans`。**

这一层只选择下一段的终点 `j`。如果 `s[i...j]` 是回文，就把这一段加入路径，让下一层从 `j + 1` 开始处理。

## 字符下标和递归深度不同

`i` 确实是字符下标，表示尚未处理的后缀从哪里开始。递归深度则表示已经选了多少段，两者不能混为一谈。

| 已经选择的子串 | 递归深度，根为 0 | 下一次调用的 `i` |
| --- | --- | --- |
| 无 | `0` | `0` |
| `"a"` | `1` | `1` |
| `"aa"` | `1` | `2` |
| `"a"`、`"a"` | `2` | `2` |

每次递归只增加一段，但这一段可以包含多个字符。因此下一层的位置是 `j + 1`，不一定是 `i + 1`。

## 先预处理哪些区间是回文

定义 `f[i][j]` 表示闭区间 `s[i...j]` 是否为回文。两端字符相等，而且中间也是回文，整个区间才是回文：

$$
f[i][j]=(s[i]=s[j])\land f[i+1][j-1]
$$

代码先把整个表初始化为 `true`，然后只计算 `i < j` 的位置：

```java
for (int i = 0; i < n; ++i) {
    Arrays.fill(f[i], true);
}
for (int i = n - 1; i >= 0; --i) {
    for (int j = i + 1; j < n; ++j) {
        f[i][j] = (s.charAt(i) == s.charAt(j)) && f[i + 1][j - 1];
    }
}
```

初始化的作用要和边界情况一起理解：

- `f[i][i]` 保持为 `true`：单个字符天然是回文。
- 两字符区间会读取 `f[i + 1][i]`：把这个下三角位置视为空区间，其值为 `true`，于是只需比较两端字符。
- 其他有效区间都会被递推覆盖，并不是把所有子串都认定为回文。

外层 `i` 从后往前遍历，是因为当前状态依赖下一行的 `f[i + 1][j - 1]`。依赖状态必须先算好。预处理需要 $O(n^2)$ 时间和空间，之后判断一个候选区间只需 $O(1)$。

## 选择、递归、撤销

回溯的核心是下面三行：

```java
ans.add(s.substring(i, j + 1));
dfs(s, j + 1);
ans.remove(ans.size() - 1);
```

1. **选择**：将回文区间 `s[i...j]` 加入当前路径。`substring` 的右端不包含在内，所以参数是 `j + 1`。
2. **递归**：当前调用暂停，让子调用枚举剩下部分的所有切法。
3. **撤销**：子调用结束后，从调用语句的下一行继续执行，删除本层刚刚选中的一段，再尝试其他终点。

这里有两类状态：

| 状态 | 不同调用之间的关系 |
| --- | --- |
| 参数 `i`、循环变量 `j` | 每个调用都有自己的值，子调用不会覆盖父调用的局部变量 |
| 字段 `ans` | 所有调用共享同一个列表，沿当前搜索路径增加、删除元素 |
| 字段 `ret` | 保存已经完成的方案，不随回溯撤销 |
| `f` 和 `n` | 搜索过程中共享，只读 |

因此，递归返回并不意味着从头执行父方法，也不意味着结束父层循环。父层记得自己选到了哪个 `j`，撤销后会继续下一个 `j`。

## 用 aab 跟踪进入与返回

下面的分支只展示回文选择；不是回文的区间直接跳过。

```text
dfs(0), ans = []
├─ 选择 "a"，进入 dfs(1)，ans = ["a"]
│  ├─ 选择 "a"，进入 dfs(2)，ans = ["a", "a"]
│  │  └─ 选择 "b"，进入 dfs(3)，保存 ["a", "a", "b"]
│  └─ "ab" 不是回文，跳过
├─ 选择 "aa"，进入 dfs(2)，ans = ["aa"]
│  └─ 选择 "b"，进入 dfs(3)，保存 ["aa", "b"]
└─ "aab" 不是回文，跳过
```

第一条路径的返回顺序尤其重要：

1. `dfs(3)` 发现 `i == n`，保存答案，立即返回。
2. 回到 `dfs(2)` 中调用 `dfs(3)` 的位置，执行下一行，删除 `"b"`，路径恢复为 `["a", "a"]`。
3. `dfs(2)` 的循环结束，返回 `dfs(1)`。这一层删除自己选的第二个 `"a"`，恢复为 `["a"]`。
4. `dfs(1)` 尝试 `"ab"`，跳过后结束。返回根调用，根调用删除第一个 `"a"`，路径恢复为 `[]`。
5. 根调用继续下一个终点，选择 `"aa"`，开始另一条分支。

子调用负责撤销它自己以及更深层的选择；父调用负责撤销父调用在进入这个子调用前做出的选择。每层的 `add` 与同层的 `remove` 一一配对。

## 为什么保存答案时必须复制

```java
if (i == n) {
    ret.add(new ArrayList<String>(ans));
    return;
}
```

`i == n` 表示所有字符都被完整覆盖，因此当前路径构成一个合法方案。

如果直接 `ret.add(ans)`，保存的只是共享列表的引用，后面的 `remove` 会同时改变已经保存的“答案”。`new ArrayList<>(ans)` 创建独立列表，后续修改路径就不会影响它。

这里只需复制列表本身。列表中的 `String` 不可变，可以安全共享字符串对象。

## 完整 Java 代码

下面保留所讨论的字段、回文表初始化和回溯写法，只补齐导入。

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    boolean[][] f;
    List<List<String>> ret = new ArrayList<List<String>>();
    List<String> ans = new ArrayList<String>();
    int n;

    public List<List<String>> partition(String s) {
        n = s.length();
        f = new boolean[n][n];
        for (int i = 0; i < n; ++i) {
            Arrays.fill(f[i], true);
        }

        for (int i = n - 1; i >= 0; --i) {
            for (int j = i + 1; j < n; ++j) {
                f[i][j] = (s.charAt(i) == s.charAt(j)) && f[i + 1][j - 1];
            }
        }

        dfs(s, 0);
        return ret;
    }

    public void dfs(String s, int i) {
        if (i == n) {
            ret.add(new ArrayList<String>(ans));
            return;
        }
        for (int j = i; j < n; ++j) {
            if (f[i][j]) {
                ans.add(s.substring(i, j + 1));
                dfs(s, j + 1);
                ans.remove(ans.size() - 1);
            }
        }
    }
}
```

这份代码按一次求解使用。如果在同一个 `Solution` 对象上多次调用 `partition`，字段 `ret` 会累积旧答案；复用对象时，应在每次求解前重新初始化结果列表。正常完成回溯后 `ans` 会恢复为空。

## 为什么能得到所有方案

**合法性**：只有 `f[i][j]` 为真才选择当前区间；下一层从 `j + 1` 开始，因此相邻段连续、没有重叠或遗漏。到达 `n` 时，整个字符串恰好被覆盖。

**完整性**：任何合法方案都有一个确定的第一段终点。循环会尝试这个终点，递归再尝试该方案的第二段终点，依次继续，最终一定到达这个方案。

**不重复**：一个方案对应唯一的一串分段终点，同一层对每个终点只尝试一次，所以不会重复生成相同方案。这里不需要额外使用集合去重。

## 复杂度为什么是指数级

长度为 $n\ge1$ 的字符串有 $n-1$ 个字符间隙，每个间隙可以切或不切。对于 `"aaaa..."`，所有子串都是回文，所有切法都合法，因此恰好有 $2^{n-1}$ 个方案。

| 部分 | 时间或空间 |
| --- | --- |
| 预处理回文表 | $O(n^2)$ 时间、$O(n^2)$ 空间 |
| 搜索并保存全部方案 | 最坏 $O(n2^n)$ 时间，包含路径复制和 Java 子串创建的成本 |
| 递归栈和当前路径 | $O(n)$ 额外空间 |
| 全部答案 | 最坏 $O(n2^n)$ 空间，包含结果列表和字符串存储 |

因此总时间为 $O(n^2+n2^n)$，通常简写为 **$O(n2^n)$**；不计输出的额外空间为 **$O(n^2)$**。答案本身就可能有指数多个，预处理只能加速回文判断，无法把枚举所有方案变成多项式时间。

## 例题与易错点速查

以下小例子用于检查切法与边界：

| 输入 | 全部分割方案 | 说明 |
| --- | --- | --- |
| `"aab"` | `["a", "a", "b"]`、`["aa", "b"]` | `"ab"` 和 `"aab"` 被剪枝 |
| `"aaa"` | `["a", "a", "a"]`、`["a", "aa"]`、`["aa", "a"]`、`["aaa"]` | 两个间隙各有切或不切，共四种 |
| `"abc"` | `["a", "b", "c"]` | 长度大于一的候选区间都不是回文 |

| 常见误解 | 正确理解 |
| --- | --- |
| 下一层一定处理下一个字符 | 下一层处理下一段，从当前终点 `j + 1` 开始 |
| `i` 就是递归深度 | `i` 是已覆盖字符数；深度是已选择的子串数 |
| 子调用返回后父调用重新开始 | 父调用从递归语句后继续执行，保留自己的 `i`、`j` |
| 返回时路径会自动恢复 | 共享的 `ans` 必须显式删除本层选择 |
| 加入 `ret` 后就不怕修改 `ans` | 必须保存路径副本，而不是保存同一个列表引用 |

理解这类回溯时，可以始终追踪四件事：**本层处理哪个后缀、这次选择哪一段、子调用从哪里开始，以及返回后撤销哪一个选择。**
