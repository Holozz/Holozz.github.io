## 先确定每根柱子上方能积多少水

LeetCode 42 给出一个非负整数数组 `height`，每根柱子的宽度都是 `1`，要求计算下雨后能够接住多少水。

对下标 `i`，设包含当前位置在内的左侧最高高度为 $L_i$，右侧最高高度为 $R_i$。该位置的积水是：

$$
w_i=\min(L_i,R_i)-height[i]
$$

两个最大值都包含当前柱子，所以这个差不会小于 `0`。最后把所有位置的积水相加即可。

例如 `[2, 0, 2]` 中间位置的两侧最高高度都是 `2`，能够积水 `2`。这条规则也说明：不能只看紧挨着当前位置的两根柱子，决定水位的是两侧能够挡水的最高柱子。

我的两次尝试分别从“先找一段的边界”和“直接确定当前一列的水位”出发。

## 第一版：用栈保留边界，再统计整个区间

我的初始想法是：用栈保存柱子的下标，遇到更高的右侧柱子时弹出中间较低的柱子，找到可用边界后，再扫描左右边界之间的整段区域。

如果某段的边界下标为 `l`、`r`，设边界水位为 $H=\min(height[l],height[r])$，就尝试逐列累加 $\max(H-height[i],0)$。

但仅有两个端点不代表可以直接按这个水位结算整段。还需要结合边界选择规则，保证不会漏掉较高水位形成的积水，也不会重复结算同一区域。

### 原始代码

**下面原样记录第一版初稿。它存在下标、高度和边界处理错误，不能作为正确答案提交。** 保留它是为了记录思路以及需要修正的地方。

```java
import java.util.Deque;
import java.util.ArrayDeque;

class Solution {
    private int calVolume(int l, int r, int[] height){
        int res = 0;
        int H = Math.min(l, r);
        for(int i=l; i<=r; i++){
            res += Math.max(H - height[i], 0);
        }
        return res;
    }
    public int trap(int[] height) {
        Deque<Integer> dq = new ArrayDeque<>();
        int res = 0;
        for(int i=0; i<height.length; i++){
            if(dq.isEmpty() || dq.peek()>=height[i]) dq.push(i);
            else if(dq.peek() < height[i]){
                dq.pop();
                while(!dq.isEmpty()){
                    if(dq.peek()<=height[i]){
                        if(dq.size() == 1){
                            int left = dq.pop();
                            res += calVolume(left, i, height);
                            dq.push(i);
                            break;
                        }
                        else dq.pop();
                    }
                    else{
                        dq.push(i);
                        break;
                    }
                }
            }
        }
        while(dq.size() >= 2){
            int right = dq.pop();
            int left = dq.peek();
            res += calVolume(right, left, height);
        }
        return res;
    }
}
```

### 初稿具体错在哪里

| 原代码                                          | 问题与修正方向                                                             |
| ----------------------------------------------- | -------------------------------------------------------------------------- |
| `dq.peek() >= height[i]` 等比较               | 栈里保存的是下标，应通过 `height[dq.peek()]` 取得高度再比较              |
| `Math.min(l, r)`                              | 水位取决于柱子高度，应取 `Math.min(height[l], height[r])`                |
| `dq.pop()` 后才进入 `while (!dq.isEmpty())` | 如果第一次弹栈就清空了栈，当前柱子没有机会入栈，需要保证当前下标最终被保存 |
| `calVolume(right, left, height)`              | 弹出的右边界下标更大，参数反了，区间循环不会执行，应按左、右顺序传入       |

例如 `[2, 0, 2]` 的正确结果是 `2`，但这份初稿返回 `0`。找到边界时，`calVolume(0, 2, height)` 使用了下标最小值 `0` 作为水位，无法得到正确积水。

### 这个思路与常见单调栈的关系

两者都借助单调栈维护可能的边界。常见写法弹出一个低柱子时，把它作为底部，立即计算一层积水：

$$
\bigl(\min(height[left],height[right])-height[bottom]\bigr)
\times(right-left-1)
$$

我的思路则是延后计算，先确定区间边界，再逐列统计整段。前者按层计算，后者按区间逐列计算。

在正确修复的区间版本中，可以在当前柱子超过所有待处理边界时结算一整段，再把当前柱子作为下一段的起点；遍历结束后，按剩余相邻边界结算。这样的各段只有端点重合，内部不重复扫描，因此仍能做到 $O(n)$ 时间和 $O(n)$ 额外空间。

这是对修正后设计的分析，不代表上面的原始代码已经正确实现了这些规则。后面我转向了状态更少的双指针方案。

## 第二版：比较左右已知最大高度

不必先找出整个区间，也可以直接判断当前哪一列的积水已经能够确定。

维护左右指针 `l`、`r`，以及两个最大值：

- `lmax` 是区间 `height[0..l]` 的最高高度，包含当前左端点。
- `rmax` 是区间 `height[r..n-1]` 的最高高度，包含当前右端点。

如果 `lmax < rmax`，对于位置 `l`，右侧已经存在至少高为 `rmax` 的挡板。即使未处理区域内还有更高的柱子，也不会改变当前位置受 `lmax` 限制的事实，因此可以确定：

$$
w_l=lmax-height[l]
$$

随后移动左指针，并把新位置的高度纳入 `lmax`。

如果 `lmax >= rmax`，同理能够确定右侧位置 `r` 的积水为 $rmax-height[r]$，然后移动右指针。两侧最大值相等时，处理任意一侧都可以；我的代码选择处理右侧。

### 双指针代码

下面原样保留第二版代码。它在本题数组非空的前提下是正确的。

```java
class Solution {
    public int trap(int[] height) {
        int res = 0;
        int l=0, r=height.length-1;
        int lmax=height[l], rmax=height[r];
        while(l < r){
            if(lmax < rmax){
                res += lmax - height[l];
                lmax = Math.max(lmax, height[++l]);
            }
            else{
                res += rmax - height[r];
                rmax = Math.max(rmax, height[--r]);
            }
        }

        return res;
    }
}
```

## 双指针里几个容易疑惑的细节

### 为什么不需要 Math.max(..., 0)

循环开始时，`lmax` 已经包含 `height[l]`，`rmax` 也已经包含 `height[r]`，所以两侧的差值都不会为负。

这依赖于更新顺序：先结算当前位置，再移动指针，并立刻把新位置纳入对应最大值。

例如 `height[++l]` 会先执行 `l++`，再访问新位置；这一行既移动指针，也为下一轮更新状态。

### 为什么比较的是最大值，而不只是当前柱高

这份代码判断哪侧可以结算的依据是 `lmax`、`rmax`。它们记录了已经发现的挡水能力；当前柱子即使很低，后面也可能有一根已经记录的高柱子作为边界。

因此，这份写法的证明围绕两侧最大值展开。不能只替换判断条件、却不检查状态含义和结算位置是否仍然匹配。

### 相遇的位置没有结算，会不会漏水

不会。较小的最大值所在一侧不断向内移动，指针最终会在某根全局最高柱子处相遇。

一旦左指针到达全局最高柱子，`lmax` 就不可能再小于 `rmax`，因此左指针会停住，右指针继续向它靠近。右侧先到达最高柱子时，也会让左侧优先推进，直到左侧同样遇到最高柱子或两指针相遇。

全局最高柱子上方不可能积水，因此 `l == r` 时直接结束不会漏算。

## 用 [3, 0, 2, 0, 4] 跟一遍

初始 `l = 0`、`r = 4`、`lmax = 3`、`rmax = 4`。

| 本轮位置     | `lmax` | `rmax` | 处理侧         | 新增积水 | 累计  |
| ------------ | -------- | -------- | -------------- | -------- | ----- |
| `l=0, r=4` | `3`    | `4`    | 左侧高度 `3` | `0`    | `0` |
| `l=1, r=4` | `3`    | `4`    | 左侧高度 `0` | `3`    | `3` |
| `l=2, r=4` | `3`    | `4`    | 左侧高度 `2` | `1`    | `4` |
| `l=3, r=4` | `3`    | `4`    | 左侧高度 `0` | `3`    | `7` |

最后左指针移动到下标 `4`，两指针相遇，返回 `7`。没有结算的最后一根柱子高度为 `4`，是全局最高柱子，自身不积水。

## 两种思路的复杂度与取舍

设数组长度为 $n$。

| 方案               | 如何结算积水                     | 时间     | 额外空间 |
| ------------------ | -------------------------------- | -------- | -------- |
| 修正后的栈区间设计 | 确定边界后逐列统计互不重叠的区间 | $O(n)$ | $O(n)$ |
| 常见单调栈         | 弹出底部时按层统计               | $O(n)$ | $O(n)$ |
| 我的第二版双指针   | 比较左右最大值，逐列确定积水     | $O(n)$ | $O(1)$ |

第一版原始代码存在正确性问题，不能因为设计目标是线性时间就当作正确解法。

双指针每轮只移动一个指针，最多执行 $n-1$ 轮，只维护几个整数，因此时间为 $O(n)$，额外空间为 $O(1)$。相较于栈设计，第二版的主要提升是减少状态和额外空间，时间复杂度的阶不变。

## 易错点速查

| 容易混淆的地方           | 应当如何判断                                       |
| ------------------------ | -------------------------------------------------- |
| 栈顶是高度还是下标       | 存的是下标，就通过 `height[dq.peek()]` 取得高度  |
| 区间水位                 | 比较两端柱子的高度，不是比较两端下标               |
| 弹栈后遗漏当前柱子       | 无论弹栈是否清空栈，都要明确当前下标如何保留       |
| 数组两端是否需要特殊加水 | 不需要；两端自身限制了水位，积水为 `0`           |
| 双指针差值是否可能为负   | 本写法的最大值包含当前柱子，因此不会为负           |
| `lmax == rmax`         | 两侧都可以结算，代码选择右侧                       |
| 空数组                   | 双指针原代码会访问越界；这里按本题非空输入约束使用 |

两次尝试围绕同一个事实展开：**一列水位由左右挡板中较低的一侧决定。栈尝试先找出能结算的区间，双指针则利用已经足够高的另一侧，提前确定当前一列的答案。**
