## 我的起点：替换第一个不小于当前数的末尾

LeetCode 300 要求返回最长严格递增子序列的长度。子序列可以不连续，但必须保持原数组中的先后顺序；严格递增意味着相邻选中元素不能相等。

我的初始写法维护一个列表 `dp`。对于当前元素 `v`，从左向右寻找第一个 `dp[j] >= v` 的位置：找到了就替换，找不到就追加。

```java
public int lengthOfLIS(int[] nums) {
    List<Integer> dp = new ArrayList<>();

    for (int v : nums) {
        int flag = -1;
        for (int i = 0; i < dp.size(); i++) {
            if (dp.get(i) >= v) {
                flag = i;
                break;
            }
        }

        if (flag == -1) dp.add(v);
        else dp.set(flag, v);
    }

    return dp.size();
}
```

这里 `dp` 的含义不是“以原数组第几个元素结尾的最长长度”，而是：

**在已经处理的前缀中，`dp[k]` 表示长度为 `k + 1` 的严格递增子序列能够取得的最小末尾值。**

长度相同的两条递增子序列，末尾较小的那条更容易接上后续元素。因此，遇到一个更小的末尾时，可以更新该长度的最优末尾，不必保留更大的末尾值。

如果所有末尾都小于 `v`，就能把 `v` 接到当前最长子序列后面，长度增加一。否则，替换第一个不小于 `v` 的末尾，长度不变，但后续扩展的条件可能变得更好。

## 为什么不能直接返回 dp

例如：

```text
nums = [3, 5, 6, 2]
dp 的变化：
[3]
[3, 5]
[3, 5, 6]
[2, 5, 6]
```

最终 `dp.size()` 为 `3`，确实是最长递增子序列的长度。但 `[2, 5, 6]` 不是原数组的子序列，因为 `2` 出现在 `5` 和 `6` 后面。

`dp` 的不同位置可以分别来自不同的候选子序列。**每个末尾值都有对应的真实子序列，不代表把这些末尾拼起来仍然是一条真实子序列。**

如果只求长度，这种压缩信息已经足够；如果要输出子序列本身，就需要额外保存形成它的历史。

## 用原数组下标记录前驱

在原来 `dp` 的基础上，增加两个数组：

| 状态             | 含义                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| `tailIndex[k]` | 当前 `dp[k]` 对应的原数组下标，即长度为 `k + 1` 的候选子序列末尾位置             |
| `prev[i]`      | 选择 `nums[i]` 作为末尾时，它在所记录子序列中的前一个元素下标；没有前驱时为 `-1` |

假设 `nums[i]` 要放入 `dp[pos]`，它将成为一条长度为 `pos + 1` 的递增子序列的末尾。

当 `pos > 0` 时，长度为 `pos` 的候选子序列末尾就是 `tailIndex[pos - 1]`，于是：

```java
prev[i] = pos == 0 ? -1 : tailIndex[pos - 1];
tailIndex[pos] = i;
```

这里必须记录原数组下标，而不是只记录 `dp` 中的位置。`dp` 和 `tailIndex` 后面还会被更新，但原数组中已经处理过的位置不会改变。

`prev[i]` 也只在处理 `i` 时赋值。以后其他长度的最优末尾发生变化，不会改掉这条已经建立的前驱关系。

### 一次完整的记录与回溯

考虑数组 `[3, 5, 6, 2, 4, 7]`：

| 下标 `i` | 当前值 | 放入位置 `pos` | 更新后的 `dp`  | `prev[i]` |
| ---------- | ------ | ---------------- | ---------------- | ----------- |
| `0`      | `3`  | `0`            | `[3]`          | `-1`      |
| `1`      | `5`  | `1`            | `[3, 5]`       | `0`       |
| `2`      | `6`  | `2`            | `[3, 5, 6]`    | `1`       |
| `3`      | `2`  | `0`            | `[2, 5, 6]`    | `-1`      |
| `4`      | `4`  | `1`            | `[2, 4, 6]`    | `3`       |
| `5`      | `7`  | `3`            | `[2, 4, 6, 7]` | `2`       |

处理 `7` 时，长度为 `3` 的候选子序列仍以原下标 `2` 的 `6` 结尾，所以 `prev[5] = 2`。

从最长子序列的末尾 `tailIndex[3] = 5` 开始，沿前驱回溯：

```text
下标：5 → 2 → 1 → 0 → -1
数值：7 → 6 → 5 → 3
```

将结果反转，得到 `[3, 5, 6, 7]`。后面出现的 `2` 和 `4` 虽然更新了较短长度的最优末尾，却没有破坏 `6 → 5 → 3` 的历史记录。

## 将线性查找改成二分查找

原代码每次从头寻找第一个 `>= v` 的位置。由于 `dp` 始终严格递增，这一步可以直接使用二分查找。

为什么 `dp` 有序？假设第一个不小于 `v` 的位置是 `pos`：

- `pos` 前面的末尾值都小于 `v`。
- 原来的 `dp[pos] >= v`，它后面的末尾值又严格大于原来的 `dp[pos]`，所以也严格大于 `v`。
- 用 `v` 替换该位置后，递增关系仍然成立；如果没有这样的位置，追加的 `v` 大于所有已有末尾值。

因此，要找的是 **第一个大于等于 `v` 的位置**，即 lower bound：

```java
int left = 0, right = dp.size();
while (left < right) {
    int mid = left + (right - left) / 2;
    if (dp.get(mid) >= v) {
        right = mid;
    } else {
        left = mid + 1;
    }
}
int pos = left;
```

搜索范围是左闭右开的 `[left, right)`，最终 `pos` 可以等于 `dp.size()`，表示应该追加。

**这里必须保留 `>=`。**对于 `[2, 2, 2]`，后续的 `2` 都应该替换位置 `0`，最终长度为 `1`。如果改成查找第一个 `> v` 的位置，相等元素也能追加，得到的就变成最长非递减子序列。

## 完整 Java 实现

下面在我的最小末尾值写法上加入前驱记录，并将内层查找替换为二分查找。`longestIncreasingSubsequence` 返回其中一条最长严格递增子序列；`lengthOfLIS` 保留题目要求的长度接口，复用同一实现。

```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

class Solution {
    public int lengthOfLIS(int[] nums) {
        return longestIncreasingSubsequence(nums).size();
    }

    public List<Integer> longestIncreasingSubsequence(int[] nums) {
        List<Integer> dp = new ArrayList<>();
        int[] tailIndex = new int[nums.length];
        int[] prev = new int[nums.length];

        for (int i = 0; i < nums.length; i++) {
            int v = nums[i];
            int left = 0, right = dp.size();

            // 查找第一个大于等于 v 的末尾值。
            while (left < right) {
                int mid = left + (right - left) / 2;
                if (dp.get(mid) >= v) {
                    right = mid;
                } else {
                    left = mid + 1;
                }
            }

            int pos = left;
            prev[i] = pos == 0 ? -1 : tailIndex[pos - 1];

            if (pos == dp.size()) {
                dp.add(v);
            } else {
                dp.set(pos, v);
            }
            tailIndex[pos] = i;
        }

        List<Integer> result = new ArrayList<>();
        int current = dp.isEmpty() ? -1 : tailIndex[dp.size() - 1];

        while (current != -1) {
            result.add(nums[current]);
            current = prev[current];
        }

        Collections.reverse(result);
        return result;
    }
}
```

如果只需要提交 LeetCode 的长度答案，可以省去前驱、末尾下标和回溯过程，直接返回 `dp.size()`。上面保留这些状态，是为了同时展示如何还原子序列。

## 正确性的关键

整个算法维护的是“每种长度的最小末尾值”。对于同样长度，较大的末尾能接上的后续数，较小的末尾也能接上，因此用更小值替换末尾不会损失未来得到更长序列的机会。

处理 `v` 时，第一个不小于它的位置是 `pos`。如果 `pos > 0`，`dp[pos - 1] < v`，所以它对应的真实子序列可以接上当前元素，得到长度 `pos + 1`。如果 `pos == 0`，当前元素本身就是一条长度为 `1` 的子序列。

另一方面，如果存在长度为 `pos + 1`、末尾小于 `v` 的旧子序列，那么该长度的最小末尾 `dp[pos]` 也应该小于 `v`，与查找结果矛盾。因此当前元素不能直接形成更长的新序列；当查找位置等于 `dp.size()` 时，才需要增加长度。

前驱下标始终来自先前处理的元素，且前驱值严格小于当前值，所以沿 `prev` 回溯得到的链在反转后既满足下标递增，也满足数值严格递增。从最长长度的末尾开始回溯，就得到一条最长递增子序列。

## 复杂度

设数组长度为 $n$，最长递增子序列长度为 $L$。

| 版本           | 查找每个元素的位置      | 总时间                                 | 额外空间 |
| -------------- | ----------------------- | -------------------------------------- | -------- |
| 初始写法       | 线性扫描，最坏 $O(n)$ | 最坏 $O(n^2)$                        | $O(n)$ |
| 二分查找并还原 | 最坏 $O(\log(L+1))$   | $O(n\log(L+1))$，最坏 $O(n\log n)$ | $O(n)$ |

`ArrayList` 的 `get` 和 `set` 是 $O(1)$，末尾追加的均摊成本是 $O(1)$。回溯和反转各需要 $O(L)$ 时间，不会改变总时间复杂度。

这里利用的是辅助列表 `dp` 的有序性，**不需要也不能先排序原数组**。例如 `[3, 1, 2]` 的答案长度是 `2`，排序后却会错误地变成 `3`。

## 边界与易错点

| 情况或误区                    | 应有结果或处理                                                      |
| ----------------------------- | ------------------------------------------------------------------- |
| `[2, 2, 2]`                 | 最长严格递增子序列长度为 `1`；二分查找第一个 `>= v` 的位置      |
| `[5, 4, 3]`                 | 长度为 `1`，当前实现还原出 `[3]`                                |
| `[3, 5, 6, 2]`              | `dp` 为 `[2, 5, 6]`，但要通过前驱还原出真实子序列 `[3, 5, 6]` |
| 多条最长子序列并存            | 当前实现返回其中一条，不保证字典序最小或下标最早                    |
| 空数组                        | 这个实现返回空列表，长度为 `0`                                    |
| 二分位置等于 `dp.size()`    | 应当追加，不能直接调用该位置的 `get` 或 `set`                   |
| `prev` 中记录 `dp` 的位置 | 应记录原数组下标，否则列表替换后会丢失历史关系                      |

这道题的思路可以分成三步：**用最小末尾值压缩候选状态，用固定的前驱下标保留一条真实路径，再利用末尾列表的有序性做二分优化。**
